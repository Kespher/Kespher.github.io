Vibe Coding分享会

0.这次分享会的背景

开学以来，我们已先后进行了三次分享，分别围绕科学上网、Google 产品的使用，以及 Git 与 GitHub 的交互操作展开。通过这几次分享，大家接触并积累了不少专业术语，包括我在内却普遍感到尚未真正动手做出属于自己的成果。

本次分享会就是帮助大家把脑海中的知识真正落地。

为了使过程更加有趣、也便于集中讲解，我们特别挑选了一个颇具趣味性的项目——“让朋友在你的电脑里赛博永生”。

一、Vibe Coding是什么？

用自然语言指挥 AI 写代码、凭感觉验收，而不是亲手敲代码。

提出：2025 年 2 月，前特斯拉 AI 负责人、OpenAI 创始成员 Andrej Karpathy（安德烈・卡帕西） 在 X（推特）上首次提出并带火了这个词。他形容这是一种 “完全跟随感觉” 的编程方式 —— 把想法说清楚交给 AI，自己几乎不碰键盘。

适合人群

想把想法快速变成可用程序的人，以及不想被代码细节拖住的人。

非技术背景者（产品、设计、运营、业务人员）独立开发者 / 创业者

  • 编程新手：可作为学习辅助——看 AI 生成的代码理解思路，但不宜完全依赖，否则基本功和排错能力难以建立。

底层逻辑

一句话理解：Vibe Coding 工具链 = AI 模型（大脑）＋ Agent（手脚）＋ 使用界面（聊天窗口/终端）。

1. 最底层：LLM模型

Claude、GPT、Gemini、千问、DeepSeek 最初都指背后的大语言模型（LLM）。聊天网站本身没有智能，只是把请求，也就是用户问的话转发给模型，模型在后端思考，再把回复以文字方式展示出来。

2. 最早的 Vibe Coding：聊天窗口（它说你做）

在聊天框描述需求 → AI 返回代码 → 手动复制粘贴运行 → 报错再把信息粘回去，来回几十次，效率很低。

3. 关键拼图：Agent（你说它做）

AI 跑在厂商服务器上，碰不到你电脑里的文件。Agent 是跑在本地电脑上的程序，能读写文件、执行命令——相当于 AI 的“手”。协作方式：AI 回复特殊格式 Function Calling（JSON 指令），Agent 识别指令并执行。

形象地说：LLM 是“大脑”，负责思考和生成内容；Agent 是“身体”，负责读写文件、执行命令，把想法真正落地。

agent开发会比LLM更简单，所以有很多厂商还有GitHub上各种个人开源项目。

4. JSON 是什么？

JSON 是电脑之间传话的一种“标准便签格式”，按“名字：内容”成对记信息。AI 给 Agent 下指令时就写这种便签，比如 {“action”: “read”, “file”: “main.py”} 意思是“去读一下 main.py 这个文件”，Agent 一看就懂，立刻照做。

5. 现在的工具生态

厂商出品：Claude Code、Codex、Google Antigravity；第三方：Cursor、Copilot；开源：OpenCode 等。Agent 与模型可自由搭配：如 OpenCode 接 Claude，国内也常用 Claude Code / Codex 接国产模型。

Agent 与模型可以自由搭配组合，但从实际体验看，同厂商的原生组合（原生模型 + Agent）配合更默契、效果更稳定。

💪方向一：双击爬行到指定位置

具体要求：
  1. 用户在 Windows 桌面的任意空白位置双击鼠标左键，

桌宠就会自动移动到双击的位置。

  1. 移动过程中，必须播放现有的爬行动画。

向左移动播放 running-left，

向右移动播放 running-right。

  1. 根据目标位置自动判断移动方向。

  2. 移动速度保持平滑自然，不要瞬间传送。

  3. 到达目标位置后，自动切换回 idle 待机动画。

  4. 如果桌宠正在移动，用户再次双击其他位置，

则更新目标位置。

  1. 桌宠不能移动到屏幕范围之外。

  2. 保留原来的鼠标拖拽、随机动画、

点击惊吓和右键菜单功能。

  1. 优先复用现有 main.js 中的移动逻辑，

不要重新编写整个项目。

🧠 方向二：接入扣子（Coze）——让桌宠拥有 AI 大脑

实现效果：

  • 让桌宠从随机弹出固定语录，升级为真正的 AI 对话。

  • 可以自定义朋友的性格、说话风格和口头禅。

  • 能够回答问题、陪伴聊天，甚至辅助学习。

  • 可以根据聊天内容触发不同的表情和动作。

大致实现流程：

  1. 创建智能体：在扣子平台创建 AI 智能体，设置角色性格和对话风格。

  2. 获取 API：将智能体发布到支持 API 调用的渠道，获取相应的调用凭证。

  3. 连接桌宠：让 Codex 编写接口调用代码，创建.env文件，写入API Token和Bot ID,将桌宠与扣子连接。

可以对 AI 说：

【请在现有桌宠项目中接入扣子 AI 智能体，实现聊天功能。用户点击桌宠后可以输入问题，程序调用扣子 API 获取回复，并通过桌宠对话气泡展示。API 密钥不要写在代码中。】

🎤 方向三：AI 语音交互——让桌宠能听会说

实现效果：

  • 用户可以直接通过麦克风与桌宠交流。

  • 桌宠能够识别用户说的话。

  • AI 根据用户的问题生成回答。

  • 桌宠通过语音朗读回答，实现双向语音交流。

大致实现流程：

  1. 语音识别（ASR）：调用语音识别服务，将麦克风录制的声音转换成文字。

  2. AI 对话：将识别出的文字发送给扣子智能体，生成回复。

  3. 语音合成（TTS）：调用语音合成服务，将 AI 回复转换成语音。

  4. 桌宠播放：通过电脑扬声器播放语音，同时显示对话气泡。

可以对AI说：

【请为现有桌宠添加 AI 语音交互功能。用户点击麦克风按钮后开始录音，通过 ASR 将语音转换为文字，再发送给扣子 AI 智能体生成回复，最后通过 TTS 将回复转换成语音播放，同时显示文字气泡。请支持麦克风权限管理和停止录音。】
